# Glance 截图分析增强 PRD

- **版本**：1.0
- **状态**：Draft
- **日期**：2026-09-23

## 1. 产品概述

Glance 帮用户理解一张截图，并把其中有用的信息转成下一步操作。本次增强聚焦截图分析本身：让用户能指定分析区域、获得更贴合截图内容的结果、围绕同一张图连续追问，并在需要时得到带来源的联网答案。

本需求基于当前实现：分享单张图片后，Glance 自动生成摘要、搜索建议、日历事件和提醒；用户也可针对图片提问。当前结果结构固定，问答没有多轮上下文，搜索建议会跳转到外部搜索引擎。参见 [`GlanceAnalysis.swift`](../Shared/GlanceAnalysis.swift)、[`AnalysisScreen.swift`](../Shared/AnalysisScreen.swift) 和 [`AIProvider.swift`](../Shared/AIProvider.swift)。

## 2. 目标与非目标

### 目标

1. 用户能选择截图中的一块区域进行聚焦分析，同时保留整张截图分析。
2. 分析结果能随截图类型变化，提供有用的文字提取、摘要、识别和操作建议。
3. 用户能在同一张截图下连续追问，后续问题理解前文。
4. 对需要实时信息的问题，Glance 能在支持的情况下给出网页来源；不支持时保留外部搜索入口。

### 非目标

- 构建语音助手或替代 Siri。
- 读取其他 App 当前屏幕、用户消息、邮件或照片图库。
- 增加跨设备对话同步或云端截图存储。
- 扩展成通用自动化平台，或自动执行未经确认的系统操作。
- 更换现有用户自带的 OpenAI-compatible provider 配置方式。

## 3. 用户与使用场景

面向会保存网页、聊天、活动海报、菜单、商品页、教程或文档截图的 iPhone 用户。

典型需求：

- “这张图整体在说什么？只解释右下角的图表。”
- “把这段文字提取出来并总结。”
- “这张活动海报的时间和地点是什么？帮我加到日历。”
- “图里这个东西是什么？有什么用途？”
- “你刚才说的第二个选项有什么区别？给我可信来源。”

## 4. 核心流程

1. 用户从系统分享菜单把一张图片交给 Glance。
2. Glance 默认分析整张图片并展示摘要与建议。
3. 用户可选择“分析局部”，用手指沿目标轮廓自由圈选后重新分析。
4. 用户查看按内容生成的结果，或进入同一截图的问答对话继续追问。
5. 用户可查看联网回答引用的来源；不支持联网回答时，可打开已有搜索引擎结果。
6. 添加日历事件或提醒前，Glance 展示拟写入内容并要求用户确认。

## 5. 功能需求

### P0：截图自由圈选与聚焦分析

- 分析页允许用户用手指沿目标轮廓自由绘制套索，圈选截图中的不规则区域；不使用矩形选区。
- 用户抬手完成圈选后，Glance 闭合起点和终点之间的路径，并显示圈选边界。用户可撤销、清除后重画。
- 用户选择“分析此区域”后，Glance 保留套索路径内的图像像素，将路径外像素遮罩为中性背景，再发送给当前视觉模型；整图继续保留在本地历史记录中。
- 可重新切回整图分析，且局部分析结果与原始整图结果有明确区分。
- 圈选路径须根据图片缩放、方向和屏幕布局正确映射到原图；路径不得因显示比例变化而偏移。
- 网络或模型失败时保留当前圈选，并提供重试；不得丢失原始图片或此前结果。

**验收标准**

- 用户能用手指沿不规则轮廓圈出文字、图表或图片主体；界面显示自由曲线套索，不出现矩形选框。
- 分析局部时，模型能看到圈内内容，圈外内容已被遮罩，不参与该次分析。
- 清除或撤销圈选后可重新绘制或回到整图分析；局部分析不会覆盖或删除原分析。

### P1：按截图内容生成分析结果

- 保留摘要和现有搜索、日历、提醒能力。
- 根据截图内容补充适用的结果类型：
  - 文字密集内容：提取文字、生成摘要、朗读摘要。
  - 海报、邀请、票券：提取时间、地点、日期并建议创建日历事件。
  - 商品、地点或图片主体：给出识别结果及相关搜索入口。
  - 教程、图表或文档：回答内容问题，必要时指出相关文字或区域。
- 不适用或模型把握不足的结果类型应隐藏或标为不确定，不得强行生成动作。
- 任何会修改日历、提醒或其他系统数据的动作，都必须先展示拟执行内容并由用户确认。
- 结果数据结构应支持新增类型而不破坏旧记录；旧版本历史仍可读取。

**验收标准**

- 同一套界面能展示不同类型截图的不同结果，不显示空白或无关的动作分区。
- 提取出的日期、地点、数字等保留原文依据；缺失信息不得推断成确定值。
- 用户确认前不会写入日历或提醒；取消后不产生副作用。

### P1：同一截图下的连续问答

- 每张截图对应一个问答线程；用户可围绕整图或当前选区连续提问。
- 后续请求携带当前截图上下文、摘要、选区信息及本线程近期问答，使“它”“第二个选项”“刚才那段”等指代能承接前文。
- 界面按时间顺序显示用户问题与模型回答，支持继续提问、重试和清空线程。
- 问答线程与截图分析记录一起保存在本机；删除截图记录时同步删除该线程。

**验收标准**

- 连续追问能引用前一轮回答中的明确项目；新建或清空线程后不再使用旧问答上下文。
- 请求失败时保留用户问题和已有对话，可单独重试。
- 历史记录重新打开后，可查看该截图关联的问答内容。

### P2：带来源的联网回答

- 对需要最新或外部事实的问题，可执行联网检索并把结果与截图上下文结合回答。
- 回答中的关键事实应链接到可打开的来源页面；来源至少显示标题和域名。
- 联网能力不可用、provider 不支持或检索失败时，明确显示状态，并保留“用 Google / Bing / DuckDuckGo 搜索”的现有入口。
- 不得把模型记忆中的信息标记成已联网核实，也不得生成不可访问或未检索到的引用。

**验收标准**

- 成功联网时，答案至少有一个与回答相关且可打开的来源；来源标注能区分网页内容与模型推断。
- 检索失败时仍能查看原截图分析和已有搜索建议。
- 对不需要联网的问题，不强制发起搜索。

## 6. 隐私、安全与兼容性

- 继续使用用户配置的 AI provider；发送请求前应让用户知道分析图片会发给该 provider。
- 局部分析默认只发送套索圈内图像，圈外像素在发送前遮罩；如后续需要整图辅助上下文，应单独说明并取得用户选择。
- 原始截图和问答记录仅按当前本地历史策略保存，用户删除记录时一并删除关联数据。
- 解析 provider 返回内容时容忍可选字段缺失；无效字段不应导致整张截图无法查看。
- 支持当前分享扩展接受的常见图片格式；长图、窄图、深色截图和文字密集截图均需可读。
- 所有可操作控件提供 VoiceOver 标签，支持动态字体和系统浅色/深色外观。

## 7. 优先级建议

1. **P0 自由圈选**：提升“只问截图这一处”的准确性和可控性。
2. **P1 连续问答**：减少用户重复描述截图内容的成本。
3. **P1 自适应结果**：让不同截图类型都能得到对应提取和动作。
4. **P2 联网回答与引用**：解决目前只能跳出 App 搜索、无法在 Glance 内核验信息的问题。
